# Wrap up: write the end-of-shift journal

Storing everything isn't memory, it's clutter. Write only what will change how a future session acts.

1. Review this conversation and pull out only **durable** items:
   - Preferences the user stated ("always…", "never…", "I prefer…")
   - Decisions made, with the one-line reason
   - Approaches that worked, and mistakes or dead ends to avoid
   - Open threads: what is half-done, and the next concrete step
2. Leave out thanks, chit-chat, things already in the code or git history, and anything already in `brain/memory/journal.md`.
3. If nothing is durable, write nothing and say so.
4. Append to `brain/memory/journal.md`:
   ```
   ## YYYY-MM-DD — <one-line session topic>
   - Pref: ...
   - Decision: ... (because ...)
   - Worked / Avoid: ...
   - Next: ...
   ```
5. Facts about the **business** (products, voice, processes, policies) belong in the wiki, not the journal. File them there with the `brain` skill's `file` steps.
6. If the journal is over ~300 lines, offer to compact older entries into wiki pages.
7. Tell the user in 2–3 lines what you saved and where.
