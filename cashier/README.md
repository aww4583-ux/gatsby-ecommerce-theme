# نظام الكاشير وإدارة المتاجر

تطبيق نقاط بيع ومحاسبة لعدة متاجر: Next.js + Supabase.
هذا المجلد مستقل عن قالب Gatsby الموجود في جذر المستودع، ومُعدّ ليُنقل إلى مستودع خاص به.

## قواعد قاعدة البيانات

- المبالغ كلها `bigint` بالدينار العراقي، بدون كسور.
- البيع يتم فقط عبر `complete_sale` في معاملة واحدة: الأسعار والتكلفة تُقرأ من القاعدة،
  المخزون يُخصم بشرط كفايته، ورقم الفاتورة تسلسلي لكل متجر بلا فجوات.
- الفواتير لا تُحذف ولا تُعدّل. الإرجاع عبر `refund_sale` (مدير أو مالك فقط) يعيد المخزون
  ويسجّل من قام به ومتى ولماذا.
- سعر التكلفة في جداول منفصلة (`product_costs`, `sale_item_costs`) لا يراها الكاشير.
- الكاشير يرى متجره فقط ومبيعات اليوم فقط (بتوقيت بغداد).
- البيع يتطلب وردية مفتوحة. عند الإغلاق: النقد المتوقع = الافتتاحي + المبيعات النقدية
  − المرتجعات النقدية المدفوعة من هذه الوردية.

## الصلاحيات في الواجهة

| القسم | المالك | المدير | الكاشير |
|---|---|---|---|
| الكاشير | ✓ | ✓ | ✓ |
| الورديات | كل المتاجر، ويغلق أي وردية | ورديات متاجره، ويغلقها | ورديته فقط |
| المنتجات (مع التكلفة) | ✓ | متاجره | ✗ |
| المصروفات | إضافة/تعديل/حذف | إضافة/تعديل | ✗ |
| الموظفون | ✓ | ✗ | ✗ |

إغلاق الوردية بالعدّ الأعمى: يُدخل الكاشير النقد المعدود أولاً، ثم يظهر المتوقع والعجز أو الزيادة.

> `SUPABASE_SERVICE_ROLE_KEY` يتجاوز كل صلاحيات قاعدة البيانات. لا تضعه أبداً في متغير يبدأ بـ
> `NEXT_PUBLIC_`. يُستخدم فقط في `src/app/(app)/staff/actions.ts` بعد التحقق من أن المستخدم مالك.

## التشغيل محلياً

يحتاج Docker و Node 20+:

```bash
npm install
npx supabase start            # يطبّق الـ migrations تلقائياً
# انسخ "API URL" و "anon key" من مخرجات الأمر السابق إلى .env.local:
#   NEXT_PUBLIC_SUPABASE_URL=...
#   NEXT_PUBLIC_SUPABASE_ANON_KEY=...
#   SUPABASE_SERVICE_ROLE_KEY=...   (service_role key — للخادم فقط، لإنشاء حسابات الموظفين)
npm run dev
```

افتح http://localhost:3000 ثم "أنشئ حساباً" لتصبح مالك النشاط.

اختصارات شاشة الكاشير: `F2` حقل الباركود، `F9` إتمام البيع، `Esc` إغلاق الإيصال.
قارئ الباركود (USB) يعمل ككيبورد: يكتب الرقم ثم Enter فيُضاف الصنف.

## تشغيل الاختبارات

تحتاج Postgres 15+ محلي (لا يحتاج Docker). السكربت يحذف قاعدة `pos_test` ويعيد إنشاءها:

```bash
scripts/test-db.sh -h localhost -p 5432 -U postgres
```

`supabase/tests/supabase_shim.sql` يحاكي `auth.uid()` وأدوار Supabase للاختبار فقط،
ولا يُطبَّق أبداً على مشروع Supabase حقيقي.

## التطبيق على Supabase

```bash
supabase link --project-ref <PROJECT_REF>
supabase db push
```

بعد التطبيق: أول مستخدم يسجّل دخوله يستدعي `create_organization` ليصبح المالك.
